# Native Bitcoin staking with PoX-5

Implemented against the official `@stacks/bitcoin-staking` **7.6.0** release from [stx-labs/stacks.js](https://github.com/stx-labs/stacks.js/tree/master/packages/bitcoin-staking). Package and transitive versions are retained in `integrations/pox5/package-lock.json`. [Source pins](../../integrations/pox5/src/source-pins.json) identify the exact deployed boot-contract sources on mainnet and testnet.

The client reads the canonical network identity, block and PoX activation; pins state calls to the block's index hash; verifies the contract source; and checks the actual bond configuration, wallet allowance, available STX, existing positions, registration window and signer grant. Missing or malformed data is an error, not zero eligibility. It discovers the next bond from the live cycle schedule when a bond number is not supplied. It does not impersonate an allowlisted staker on the public network.

The public testnet check in [testnet-eligibility.json](../../integrations/pox5/evidence/testnet-eligibility.json) read the dedicated test wallet. Bond 10 was locked; bond 11 was open. **Its allowance was zero on both bonds.** The required paired commitment for 100,000 sats was 50,000 uSTX. No native BTC was locked and no registration was submitted. This is an observed access requirement, not a missing faucet balance. The [official onboarding instructions](https://pox-5.vercel.app/docs/development/onboarding) specify that the bond administrator publishes the allowlist; the integrator cannot grant itself access.

An eligible observation can prepare a lock plan using the official SDK. The plan binds the Stacks principal, compressed Bitcoin public key, early-exit script, amount and maximum lock height. A fresh observation must still agree; the resulting height and output script must match canonical contract reads. This remains **preparation only**: ownership verification, signer-manager public acceptance, Bitcoin funding/inclusion proofs, registration signing and public recovery evidence are not completed by a read-only plan. The client exposes no broadcast method. Do not turn `fundingAllowed: false` into a deposit button.

Saved public recovery records can be reloaded after a browser restart. The recovery helper reconstructs the lock script and address, verifies the supplied original transaction's ID, output index, amount and script, checks the height-based timelock and maximum fee, and builds an unsigned normal-path recovery transaction. It does not prove the output remains unspent or the caller's reported Bitcoin height; a signing application must establish those facts from the correct Bitcoin chain. The early-exit path additionally needs the bond cosigner and is not presented as a unilateral withdrawal.

Stacks public testnet's Bitcoin side is **regtest**, which is different from Babylon/Lombard Signet. Mainnet uses Bitcoin mainnet. No network is inferred from an address prefix alone. Native BTC stays locked on Bitcoin even if registration subsequently fails or misses its deadline; this consequence is shown with each observation. The [paired BTC documentation](https://pox-5.vercel.app/docs/development/paired-btc) describes the full registration and recovery sequence.

Run `npm ci --ignore-scripts`, `npm test`, and `npm run verify:testnet` from `integrations/pox5/`. The first command installs pinned dependencies, the second uses deterministic fixtures and the real SDK, and the final command performs public read-only checks. No wallet credential is needed.
